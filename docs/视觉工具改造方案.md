# 纯文本模型视觉能力改造方案（model_vision + 视觉工具）

> 目标：给 `naturel_gpt` 插件中「不支持视觉输入」的 LLM profile 增加一个 `model_vision` 配置（默认 `deepseek-flash`），
> 让纯文本模型在收到图片时，通过一个**最简视觉工具**把图片委托给视觉模型理解，再以纯文本结果回传给主模型。
> 参考项目：https://github.com/QwenLM/Qwen-MM-Plugins （已 clone 到 `_temp_qwen_ref/Qwen-MM-Plugins`，仅取其最核心部分）。

---

## 一、参考项目核心提炼（我们只借用这两点）

Qwen-MM-Plugins 里真正"最核心"的是 `api` 能力下的 `vl/vision_chat.py` 与其依赖的两个函数：

1. **`encode_image_source(source)`**（`src/shared/api_openai.py`）
   - 把「URL / data URL / 本地文件路径」统一转成 OpenAI 的 `image_url` 内容块；本地文件 base64 成 `data:<mime>;base64,...`。
   - **插件已有等价物**：`image_cache.py` 的 `resolve_urls()`（URL → base64 data URI，带 LRU 缓存 + QQ Referer/UA + 坏 URL 记忆）。
2. **`call_openai_chat(base_url, api_key, model, messages, ...)`**（`src/shared/api_openai.py`）
   - OpenAI-compatible 客户端，重试可恢复错误。
   - **插件已有等价物**：`openai_func.py` 的 `_request_openai_compatible()`（httpx 直连，`{base_url}/chat/completions`）。

而 `vision_chat` 工具本体就是：`content = [encode_image_source(img), {"type":"text","text": prompt}]` → `call_openai_chat(...)` → 返回 `choices[0].message.content`。

**结论：视觉工具 = 插件现有的 `image_cache.resolve_urls` + `_request_openai_compatible` 的一层薄胶水，无需引入 `openai` SDK、无需外置 MCP/OSS/ffmpeg。** 参考项目的 OCR / grounding / omni 等均属"外置能力"，本次不取。

## 二、方案总览

- 现有 `multimodal` 布尔仍是「主模型是否原生收图」的开关。
- 新增 profile 字段 **`model_vision`**：纯文本模型把图片委托给哪个视觉模型，默认 `"deepseek-flash"`。
- 判定规则（向后兼容）：

| profile 配置 | 行为 |
|---|---|
| `multimodal: true`（缺省 `model_vision`） | 现状：图片以 `image_url` 直接发给主模型（grok/kimi 等原生多模态不受影响） |
| `multimodal: false` 且 `model_vision` 非空 | **新**：请求层剥离图片，注册 `vision` 工具，模型看到 `[图片N]` 后调工具问图，工具用 `model_vision` 模型回答 |
| `multimodal: false` 且 `model_vision` 为空 | 现状：剥离图片、不注册工具（降级为纯文本） |

数据流（纯文本模型 + 用户发图）：

```
用户发图
  └─ gen_chat_payload → 文本含 "[图片1] …" + image_urls 列表
       └─ matcher 记录触发消息(含 images) → _snapshot_request_profile 带上 model_vision
            └─ 请求层剥离 image_url（文本里的 [图片N] 保留）→ 工具 schema 注入 vision
                 └─ 主模型输出 tool_call: vision(image_index=1, prompt="…")
                      └─ vision.run: image_cache.resolve_urls → 拼 image_url+prompt → 调 model_vision 模型
                           └─ 返回文字描述 → 主模型下一轮读描述 → 生成最终纯文本回复
```

## 三、配置设计

`OPENAI_PROFILES` 的真实 profile 条目是 `Dict[str, Any]`，自由扩展字段用 `.get(key, default)` 读取即可，**无需**改动 `Config` 类 / `CONFIG_TEMPLATE`（记忆里"三处登记"只针对顶层键）。注意 `default` 键是指针（字符串），所以读取 profile 统一走 `config.get_profile(name)`。

```yaml
OPENAI_PROFILES:
  default: ds                 # 默认指针：值为 profile 名（不是模型配置）
  ds:                         # 纯文本主模型（deepseek-flash），走视觉工具
    api_keys: [...]
    base_url: https://opencode.ai/zen/go/v1
    multimodal: false         # 关键：标记主模型原生不收图
    model_vision: deepseek-flash  # 视觉模型名，默认 "deepseek-flash"，与主模型同网关
    # 可选覆盖（不同端点/不同 key 时）：
    # model_vision_base_url: ...
    # model_vision_api_keys: [...]
    # model_vision_max_tokens: 1024
    model: deepseek-flash
    model_mini: deepseek-flash
  kimi:
    ...
    multimodal: true          # 原生多模态，走现状，model_vision 忽略
    model: kimi-k3
```

字段语义：

- `model_vision`: `str`，视觉模型名，默认 `"deepseek-flash"`。仅在 `multimodal: false` 时生效。
- `model_vision_base_url`: 可选，缺省复用本 profile 的 `base_url`（同网关场景最省事）。
- `model_vision_api_keys`: 可选，缺省复用本 profile 的 `api_keys`。
- `model_vision_max_tokens`: 可选，缺省 1024。

> 注意：`model_vision` 的默认 `"deepseek-flash"` 需确认就是网关上的视觉模型 ID；若是别的名字（如 `qwen-vl-max` / `gpt-4o`），改这里即可。

## 四、视觉工具设计（核心，新文件 `llm_tool_plugins/vision.py`）

### 1. schema（OpenAI function 格式，与 `memory.py`/`tavily_search.py` 一致）

```python
schema = {
    "type": "function",
    "function": {
        "name": "vision",
        "description": (
            "视觉理解工具。当用户消息中出现 [图片N] 占位符、且需要识别/描述/理解图片内容时调用。"
            "image_index 对应 [图片N] 的 N（从 1 开始）。只能对当前这条消息里的图片提问。"
        ),
        "parameters": {
            "type": "object",
            "properties": {
                "image_index": {"type": "integer", "description": "图片序号，对应 [图片N] 的 N"},
                "prompt": {"type": "string", "description": "你想问这张图的问题，如：图里有什么、文字是什么"},
            },
            "required": ["image_index", "prompt"],
        },
    },
}
```

### 2. run 核心逻辑（伪代码，复用现有能力）

```python
async def run(args, config):
    idx = int(args.get("image_index", 1))
    prompt = str(args.get("prompt") or "详细描述这张图片的内容")

    from ..openai_func import TextGenerator
    tg = TextGenerator.instance
    # 1) 取当前触发消息的图片 URL 列表（ContextVar 快照，见第五节）
    urls = tg._current_trigger_images or []
    if idx < 1 or idx > len(urls):
        return "图片序号超出范围，请检查 [图片N]。", []
    url = urls[idx - 1]

    # 2) URL → data URI（复用 image_cache，含缓存/UA/Referer/坏URL记忆）
    from .. import image_cache
    data_uri = await image_cache.resolve_urls([url])
    if not data_uri:
        return "图片无法下载（可能已过期），请让用户重新发送。", []

    # 3) 组装 OpenAI 多模态请求（等价于参考项目的 encode_image_source + call_openai_chat）
    messages = [{"role": "user", "content": [
        {"type": "image_url", "image_url": {"url": data_uri[0]}},
        {"type": "text", "text": prompt},
    ]}]

    # 4) 调视觉模型（复用插件 httpx 直连，非流式）
    vis = tg._current_vision_config  # {model, base_url, api_key, max_tokens}
    resp = await tg._request_openai_compatible({
        "model": vis["model"],
        "base_url": vis["base_url"],
        "api_key": vis["api_key"],
        "messages": messages,
        "max_tokens": vis["max_tokens"],
        "stream": False,
    })
    return resp["choices"][0]["message"]["content"] or "", []
```

> 与参考项目 `vision_chat.handle()` 一一对应：`encode_image_source` → `image_cache.resolve_urls`；`call_openai_chat` → `_request_openai_compatible`。未引入任何新依赖。

### 3. 工具注册 / 门控

- `vision.py` 走工具自动发现（导出 `schema` + `run`），模块级不做 `should_load` 拦截。
- 在 `llm_tools.get_tool_schemas(config, chat_key)` 里按**当前群 profile** 过滤（仿 `nas_game_list` 的白名单过滤模式）：
  - 只有 `chat_key` 对应的 profile 满足「`multimodal` 为 false 且 `model_vision` 非空」时，才把 `vision` 的 schema 加入本轮 tools。
  - 纯文本模型才看到这个工具，原生多模态 profile 不暴露，避免误导模型。

### 关键点：`[图片N]` → 真实 URL 的映射

- `utils._extract_message_text_and_images` 已按顺序给图片编号 `[图片1..N]`，`image_urls` 与之同序。
- 触发消息的 `ChatMessageData.images` 与之一致，因此 `image_index` 直接索引 `images[N-1]`。
- 为避免多群并发串数据，触发图片用 **ContextVar** 快照（同 `_current_chat_key`），不要挂在单例实例变量上。

## 六、边界与注意点

1. **图片下载失败**（QQ `rkey` 过期 400 属预期）：`image_cache` 已返回空并记忆坏 URL；工具返回「图片过期，请重新发送」。
2. **视觉模型调用失败/超时**：`run` 捕获异常返回错误文本，主模型自然降级回复，不中断主流程。
3. **费用/统计**：视觉调用是额外一次 API 请求，可在 `run` 里调 `stats.record_model_usage(model_vision, ...)` 计入统计；其 usage 走非流式响应。
4. **token 预算**：图片以 data URI 发给视觉模型，`model_vision_max_tokens` 控制回答长度（默认 1024）。
5. **多图**：`image_index` 支持 1..N；一张图多次提问可连续调用。
6. **原生多模态 profile 不受影响**：`multimodal:true` 走现状，`model_vision` 被忽略。
7. **兼容性**：未配置 `model_vision` 的旧配置行为与现在完全一致。

## 七、落地步骤（分阶段）

1. **阶段 1（配置+门控）**：加 `model_vision` 默认值 → `_snapshot_request_profile` 透传 → `get_tool_schemas` 门控。
2. **阶段 2（工具本体）**：新增 `vision.py`，复用 `image_cache` + `_request_openai_compatible`；在 `stream_response` 写入图片快照 + 视觉配置快照。
3. **阶段 3（提示词+展示）**：`chat_prompt` 追加视觉提示；`rg model` 展示视觉模式。
4. **阶段 4（联调）**：某群 profile 设 `multimodal: false` + `model_vision: deepseek-flash`，发图验证「文本模型 → vision 工具 → 视觉模型 → 文本描述」全链路；检查 `data/naturel_gpt/logs/*.latest.json` 确认 tool_calls 与图片剥离正确。

## 附录：从参考项目可借鉴的优化点（针对 image_cache / _request_openai_compatible）

对比 `src/shared/{api_openai,retry,image}.py` 后，两块各有可借鉴处：

### A. 瞬时错误退避重试（高价值，来自 `retry_call` + `_RETRYABLE_STATUS`）

- 参考：`call_openai_chat` 对 429/500/502/503/504 及限流/超时/连接/InternalServer 错误退避重试，带 jitter。
- 现状：`_request_openai_compatible`/`_stream_iter_openai` 遇 4xx/5xx 直接抛 RuntimeError，无网络层重试（现有重试是 matcher 的业务级语义，额外烧 token）。
- 建议：
  - 非流式 `_request_openai_compatible`（视觉工具用）：加 async 退避重试，仅对 429/5xx/连接/超时，`asyncio.sleep(base*attempt + jitter)`，2~3 次，可顺带 rotate key。
  - 流式 `_stream_iter_openai`：只在收到首个 chunk 前重试，已产出内容不重发。

### B. 图片预处理缩放/重编码（高价值，来自 `smart_resize` + `process_image`）

- 参考：发图前按 patch grid（32 对齐）+ 像素预算（1024 token ≈ 1M 像素）+ JPEG/PNG 重编码。
- 现状：原始字节直接 base64（单图 10MB 上限），视觉模型对超大图有 token 上限（Qwen 16M 像素/16384 token），易被拒或吃满预算。
- 建议：视觉工具下载后先 PIL 缩放重编码到视觉预算内再 base64。PIL 已在依赖内（matcher 拍立得已用），零新增依赖；gif 取首帧。

### C. 可选

- 下载重试 + 错误分类：网络抖动/超时/5xx 重试 1~2 次；4xx（QQ rkey 过期 400）不重试，保留坏 URL 记忆。
- httpx 客户端复用：`image_cache` 改模块级单例 `AsyncClient` 复用连接池。

### D. 不必借鉴

`require_dep/require_file`、`cache.py` 磁盘内容寻址缓存、`env.py` dotenv、grounding/OCR/draw_boxes/OSS/omni；`retry_call` 的同步 `time.sleep` 需改 `asyncio.sleep` 适配异步。
